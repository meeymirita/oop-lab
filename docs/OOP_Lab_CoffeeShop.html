1. Зачем вообще ООП: массив с функциями vs объект #

Представьте кассу кофейни без объектов. Заказ — массив, цена считается функцией:

$item = ['drink' => 'latte', 'size' => 'L', 'extras' => ['oat', 'shot'], 'qty' => 2];

function itemPrice(array $item): int
{
    $base = match ($item['drink']) { 'espresso' => 150, 'latte' => 250, 'cappuccino' => 230 };
    $size = match ($item['size'])  { 'S' => 0, 'M' => 40, 'L' => 80 };
    $extras = 0;
    foreach ($item['extras'] as $e) { $extras += match ($e) { 'oat' => 60, 'shot' => 70, 'vanilla' => 40 }; }
    return ($base + $size + $extras) * $item['qty'];
}

Работает. Теперь пять вопросов, на которые этот код отвечает плохо:

Общий знаменатель: у массива нет поведения и нет гарантий. Он хранит что угодно, и вся логика живёт снаружи — в функциях, которые надо не забыть вызвать. Объект — это данные плюс код, который единственный имеет право их менять. ООП начинается ровно здесь: когда вы говорите «пусть заказ сам знает, что с ним можно делать».

2. Азбука ООП в PHP — каждое слово на примере кофейни #

Тринадцать понятий, без которых не прочитать ни одного класса. Каждое — определение в одну строку и три-пять строк кода. Не пытайтесь запомнить всё сразу: в сессии 1 вы напишете это руками, и тогда сложится.

2.1 Класс и объект

Класс — описание: какие данные и какое поведение. Объект (экземпляр) — конкретная вещь, созданная по этому описанию через new. Класс Latte один; объектов-латте — сколько заказали.

class Latte {}                      // описание (пока пустое)
$a = new Latte();                   // объект №1
$b = new Latte();                   // объект №2 — другой, хотя класс тот же
var_dump($a === $b);                // false: объекты сравниваются по идентичности, не по содержимому

2.2 Свойство и метод

Свойство — переменная, живущая внутри объекта (его состояние). Метод — функция, живущая внутри объекта (его поведение). $this — «тот объект, у которого вызвали метод».

class Latte
{
    public string $size = 'M';                       // свойство с значением по умолчанию

    public function price(): int                     // метод
    {
        return 250 + ($this->size === 'L' ? 80 : 0); // $this->size — свойство ЭТОГО объекта
    }
}
$l = new Latte();  $l->size = 'L';  echo $l->price();   // 330

2.3 Конструктор и promotion

Конструктор __construct вызывается при new и приводит объект в корректное начальное состояние. Если объект не может существовать без размера — размер обязателен в конструкторе, а не «потом присвоим». Promotion (PHP 8): параметр конструктора с модификатором видимости сразу становится свойством.

class Latte
{
    public function __construct(private string $size) {}   // = объявить private string $size + $this->size = $size
}
$l = new Latte('L');          // размер задан один раз, при рождении объекта
$l = new Latte();             // ArgumentCountError — без размера латте не бывает

2.4 Видимость: public / protected / private

public — доступно всем. private — только коду этого класса. protected — этому классу и его наследникам. Правило: по умолчанию private; открывайте только то, что действительно нужно снаружи.

class Order
{
    private array $lines = [];                        // снаружи не видно и не изменить

    public function add(string $drink, int $qty): void
    {
        if ($qty < 1) { throw new InvalidArgumentException('qty must be >= 1'); }
        $this->lines[] = [$drink, $qty];              // единственный способ попасть внутрь — через проверку
    }
}
$o = new Order();  $o->add('latte', 2);
$o->lines[] = ['latte', -5];                          // Error: Cannot access private property Order::$lines

2.5 Типы

Типы параметров, возвращаемых значений и свойств — это часть контракта. function add(Beverage $b, int $qty): void говорит: «сюда можно передать только напиток и целое число, назад ничего не вернётся». PHP проверит это при вызове. Объявите declare(strict_types=1) в начале файла — иначе '2' тихо превратится в 2.

2.6 readonly и неизменяемость

readonly-свойство можно записать один раз — в конструкторе. Объект, у которого все свойства readonly, после создания не меняется; любое «изменение» — это новый объект. Так устроены деньги, даты, размеры: $price->add($tax) возвращает новую сумму, старая остаётся прежней.

final readonly class Money
{
    public function __construct(public int $cents) {}
    public function add(Money $other): Money { return new Money($this->cents + $other->cents); }   // новый объект
}
$a = new Money(250);  $b = $a->add(new Money(80));
echo $a->cents;        // 250 — не изменился
$a->cents = 999;       // Error: Cannot modify readonly property Money::$cents

2.7 static, self, const

Статический метод/свойство принадлежит классу, а не объекту: вызывается Money::rub(250), без new. Типичное применение — именованные конструкторы (фабрики): Money::rub(), Money::fromCents(). self — «этот класс» внутри его кода. const — константа класса.

final readonly class Money
{
    private const int CENTS_PER_RUB = 100;                       // typed constant — PHP 8.3
    private function __construct(public int $cents) {}           // private: снаружи создаём только через фабрики
    public static function rub(int $rubles): self { return new self($rubles * self::CENTS_PER_RUB); }
}
$m = Money::rub(250);            // читается лучше, чем new Money(25000)

2.8 Наследование: extends, parent, abstract, final

class Latte extends Drink — латте получает всё, что есть у Drink, и может добавить своё или переопределить. parent:: — обратиться к версии родителя. abstract класс нельзя создать через new — он только заготовка; abstract метод — «ребёнок обязан реализовать». final — «наследовать / переопределять нельзя». Подробно — раздел 3.

2.9 Интерфейс: implements

Интерфейс — список методов без тел. class CashPayment implements PaymentMethod обещает: «у меня есть все методы из PaymentMethod». Класс может реализовать много интерфейсов. Интерфейс — это тип: function pay(PaymentMethod $m) примет любой класс, который его реализует. Подробно — раздел 4.

2.10 Enum

enum — тип с конечным набором значений. Вместо строки 'L', которая может быть 'l', 'XL' или опечаткой, — Size::Large, других значений не существует. У enum могут быть методы: Size::Large->surcharge().

enum Size: string
{
    case Small = 'S';  case Medium = 'M';  case Large = 'L';

    public function surcharge(): int { return match ($this) { self::Small => 0, self::Medium => 40, self::Large => 80 }; }
}
Size::from('L')->surcharge();     // 80;  Size::from('XL') → ValueError

2.11 Исключения

Исключение — способ объекта сказать «в этом состоянии я это сделать не могу» так, чтобы вызывающий код не мог проигнорировать. DomainException — нарушено бизнес-правило (нет товара, заказ уже оплачен); InvalidArgumentException — передали ерунду (qty = −1). Свои исключения — это тоже классы: final class PaymentFailed extends DomainException.

2.12 Замыкания и first-class callable

Функция как значение: $fn = fn (Money $m) => $m->add(...). $order->add(...) (три точки) — метод объекта, превращённый в замыкание. Понадобится в сессии 4, чтобы обернуть метод в объект-стратегию.

2.13 Композиция: объект внутри объекта

Самая частая связь между классами — не наследование, а «содержит»: заказ содержит строки, строка содержит цену, касса содержит политику скидок. Объект получает другие объекты в конструктор и вызывает их методы. Половина лабы — про то, когда выбирать композицию, а когда наследование (раздел 5).

3. Четыре принципа ООП — на кофейне #

По каждому: бытовое определение, где он в проекте, как выглядит нарушение, типичная ошибка новичка.

3.1 Абстракция — «что», а не «как»

Определение. Выделить существенное и спрятать остальное. Абстракция — это контракт: что объект обещает, без указания, как он это делает.

В проекте. Интерфейс Beverage { name(); price(); }. Кассе всё равно, латте это, чай или латте с двумя сиропами и овсяным молоком — она зовёт price(). PaymentMethod { charge() } — контроллер оплаты не знает, наличные это или карта.

Нарушение. Касса знает конкретику: if ($b instanceof Latte && $b->hasOatMilk()). Теперь новый напиток требует править кассу.

Ошибка новичка. Абстракция ради абстракции: интерфейс с 12 методами, из которых нужны 2. Хорошая абстракция маленькая: Beverage — два метода.

3.2 Инкапсуляция — защита инвариантов

Определение. Данные и код, который их меняет, живут вместе; снаружи доступно только безопасное. Цель — чтобы объект нельзя было привести в некорректное состояние.

В проекте. Order: строки заказа private; добавить можно только через add(), который проверяет количество и статус; оплатить пустой заказ нельзя; после оплаты добавить нельзя. Инварианты («оплаченный заказ не меняется», «сумма ≥ 0», «эспрессо не бывает большим») живут в одном месте — в классе.

Нарушение. Геттер + сеттер на каждое поле: setStatus('paid') — и любой контроллер переведёт заказ в любой статус, минуя проверки. Это публичное поле с лишним синтаксисом, а не инкапсуляция.

Ошибка новичка. Считать, что private — «для приличия». Нет: каждое private — гарантия, которую можно не проверять снаружи.

3.3 Наследование — «является» и общий скелет

Определение. Потомок получает члены родителя, добавляет своё, переопределяет нужное. Семантика: потомок является частным случаем родителя.

В проекте. abstract class Drink знает, как складывать базовую цену с надбавкой за размер и как собирать название; Latte, Espresso, Tea знают только свою цену и своё название. Общий код — один раз. AbstractAmqpWorker в сессии 5 — то же самое для воркеров.

Нарушение. Наследование ради кода, а не смысла: class Order extends Money, чтобы «у заказа была сумма». Заказ не является деньгами. Или лестницы: LatteWithOatMilk extends Latte, LatteWithOatMilkAndShot extends LatteWithOatMilk… — сессия 3 покажет, во что это превращается.

Ошибка новичка. Глубокие иерархии. Два уровня — почти всегда потолок.

3.4 Полиморфизм — один вызов, много поведений

Определение. Код работает через общий контракт и не знает конкретной реализации; поведение выбирается по реальному типу объекта во время выполнения — без if/switch у вызывающего.

В проекте. foreach ($menu as $drink) echo $drink->price() — четыре класса, одна строка. $this->discount->discountFor($order) — касса не знает, «10 % всем» это или «−20 % в happy hour». $method->charge() — наличные или карта.

Нарушение. match ($drink->type) { 'latte' => 250, 'tea' => 120 } вне класса — «полиморфизм на if'ах». Новый напиток = править все такие match в проекте.

Ошибка новичка. Думать, что полиморфизм — только про наследование. Через интерфейс он даже сильнее: Cash, Card и поддельный шлюз в тесте не родственники, но взаимозаменяемы.

ЧЕТЫРЕ ПРИНЦИПА — ОДНА ИДЕЯ С ЧЕТЫРЁХ СТОРОН

Абстракция задаёт контракт → инкапсуляция прячет всё, что не контракт → полиморфизм позволяет подставлять разные реализации → наследование — один из способов эти реализации получать (второй — композиция, и он в лабе будет встречаться чаще).

Всё интерфейсами. Latte implements Beverage должен сам считать «база + размер» и собирать название. Четыре напитка — четыре копии. Интерфейс не умеет делиться кодом.

Всё абстрактными классами. CashPayment extends AbstractPayment — и всё, другого родителя не будет. А в тесте нужен поддельный PaymentMethod за три строки — с абстрактным классом тащите его конструктор и состояние. И класс не сможет быть одновременно PaymentMethod и, скажем, Refundable.

Правило. Абстрактный класс — для «скелет + дырки». Интерфейс — для всего, что хочется подменять. В типичном проекте на один абстрактный класс — десять интерфейсов.

Абстрактный класс: два вида «дырок»

abstract class Drink
{
    abstract protected function basePrice(): Money;     // абстрактный метод: ребёнок ОБЯЗАН реализовать
    protected function note(): string { return ''; }     // хук: есть дефолт, ребёнок МОЖЕТ переопределить

    final public function price(): Money                 // скелет: менять нельзя
    {
        return $this->basePrice()->add($this->size->surcharge());
    }
}

Абстрактный метод — для того, без чего класс бессмыслен (напиток без цены). Хук — для того, что нужно одному наследнику из пяти (у чая есть примечание про заваривание, у остальных нет). Если сделать note() абстрактным, четыре класса напишут пустой метод — шум.

5. Наследование vs композиция — главный выбор #

Задача: латте с овсяным молоком и двойным шотом. Два способа.

Первый объект — деньги. Не потому что это сложно, а потому что на нём видно всё: свойство, конструктор, метод, $this, readonly, static-фабрика, private-конструктор.

<?php
// laravel-app/lab0/Money.php — только класс; демонстрация будет в 02_money.php
declare(strict_types=1);

final readonly class Money
{
    private const int CENTS_PER_RUB = 100;

    // private-конструктор: снаружи создать Money можно ТОЛЬКО через фабрики ниже
    private function __construct(public int $cents) {}

    public static function rub(int $rubles, int $kopecks = 0): self
    {
        return self::fromCents($rubles * self::CENTS_PER_RUB + $kopecks);
    }

    public static function fromCents(int $cents): self
    {
        if ($cents < 0) {
            throw new InvalidArgumentException("Money cannot be negative: {$cents}");
        }
        return new self($cents);
    }

    public static function zero(): self { return new self(0); }

    // каждая операция возвращает НОВЫЙ объект — старый не меняется
    public function add(Money $other): self       { return new self($this->cents + $other->cents); }
    public function subtract(Money $other): self  { return self::fromCents($this->cents - $other->cents); }
    public function multiply(int $factor): self   { return self::fromCents($this->cents * $factor); }
    public function percent(int $p): self         { return new self(intdiv($this->cents * $p, 100)); }

    public function isGreaterThan(Money $other): bool { return $this->cents > $other->cents; }
    public function equals(Money $other): bool        { return $this->cents === $other->cents; }

    public function format(): string
    {
        return number_format($this->cents / 100, 2, ',', ' ') . ' ₽';
    }
}

Поэтому equals() сравнивает содержимое, а readonly запрещает менять — «изменить» значение так же бессмысленно, как изменить число 5. Инкапсуляция: копейки хранятся целым числом (никаких float с 0.1+0.2), и это решение скрыто: снаружи видны только rub(), add(), format(). Захотите добавить валюту — все правки в одном файле. Private-конструктор + static-фабрики: объект нельзя создать в обход проверки на отрицательность.
🔬 Под капотом: readonly защищает свойство, не объект внутри него; и зачем self в возвращаемом типе

readonly int $cents — переприсвоить нельзя, всё. Если бы свойство было объектом (readonly Carbon $at), сам объект внутри можно было бы мутировать ($this->at->addDay()). Полная неизменяемость — это readonly плюс дисциплина: внутри VO держать только скаляры и другие VO.

Шаг 2.3Фабрика через enum DrinkType и GET /api/menu#

Запрос приносит строку "latte". Где-то она должна превратиться в new Latte(...). Это «где-то» должно быть ровно одно — фабрика. Удобнее всего — enum с методом:

<?php
// app/Domain/Menu/DrinkType.php
declare(strict_types=1);

namespace App\Domain\Menu;

enum DrinkType: string
{
    case Espresso   = 'espresso';
    case Latte      = 'latte';
    case Cappuccino = 'cappuccino';
    case Tea        = 'tea';

    /** Единственное место в проекте, где строка превращается в класс напитка. */
    public function make(Size $size): Drink
    {
        return match ($this) {
            self::Espresso   => new Espresso($size),
            self::Latte      => new Latte($size),
            self::Cappuccino => new Cappuccino($size),
            self::Tea        => new Tea($size),
        };
    }
}
<?php
// app/Http/Controllers/MenuController.php

namespace App\Http\Controllers;

use App\Domain\Menu\{DrinkType, Size};
use DomainException;
use Illuminate\Http\JsonResponse;

final class MenuController extends Controller
{
    public function index(): JsonResponse
    {
        $menu = [];
        foreach (DrinkType::cases() as $type) {
            foreach (Size::cases() as $size) {
                try {
                    $drink = $type->make($size);
                } catch (DomainException) {
                    continue;                                   // «большой эспрессо» — просто нет в меню
                }
                $menu[] = ['type' => $type->value, 'size' => $size->value, 'name' => $drink->name(), 'price' => $drink->price()->format()];
            }
        }
        return response()->json($menu);
    }
}

Enum-фабрика короче и типобезопаснее: параметр — не строка, а DrinkType, и невалидное значение отсекается ещё до вызова. Минус: enum не может иметь зависимостей (у него нет конструктора). Как только фабрике понадобится, например, прайс-лист из БД, — переезжайте в класс. В сессии 4 PaymentType столкнётся именно с этим.

<?php
// app/Domain/Order/OrderStatus.php
declare(strict_types=1);

namespace App\Domain\Order;

enum OrderStatus: string
{
    case Draft = 'draft';
    case Paid  = 'paid';
    case Ready = 'ready';

    /** Граф переходов — в одном месте. Всё, чего здесь нет, — запрещено. */
    public function canTransitionTo(self $to): bool
    {
        return in_array($to, match ($this) {
            self::Draft => [self::Paid],
            self::Paid  => [self::Ready],
            self::Ready => [],
        }, true);
    }
}

// app/Domain/Order/Order.php
declare(strict_types=1);

namespace App\Domain\Order;

use App\Domain\Menu\Beverage;
use App\Domain\Money;
use DomainException;
use InvalidArgumentException;

final class Order
{
    /** @var list<OrderLine> */
    private array $lines = [];
    private OrderStatus $status = OrderStatus::Draft;

    private function __construct(
        public readonly string $id,
        public readonly ?string $email,
    ) {}

    public static function open(string $id, ?string $email = null): self
    {
        return new self($id, $email);
    }

    /** Восстановление из хранилища — без проверок add(): данные уже были валидны при сохранении. */
    public static function restore(string $id, ?string $email, array $lines, OrderStatus $status): self
    {
        $order = new self($id, $email);
        $order->lines  = $lines;
        $order->status = $status;
        return $order;
    }

    public function add(Beverage $beverage, int $qty = 1): void
    {
        if ($this->status !== OrderStatus::Draft) {
            throw new DomainException("Заказ в статусе {$this->status->value}, добавлять нельзя");
        }
        if ($qty < 1) {
            throw new InvalidArgumentException("Количество должно быть ≥ 1, получено {$qty}");
        }
        $this->lines[] = new OrderLine($beverage->name(), $beverage->price(), $qty);
    }

    public function markPaid(): void
    {
        if ($this->lines === []) { throw new DomainException('Нельзя оплатить пустой заказ'); }
        $this->transition(OrderStatus::Paid);
    }

    public function markReady(): void { $this->transition(OrderStatus::Ready); }

    public function subtotal(): Money
    {
        $sum = Money::zero();
        foreach ($this->lines as $line) { $sum = $sum->add($line->total()); }
        return $sum;
    }

    public function itemCount(): int { return array_sum(array_map(fn (OrderLine $l) => $l->qty, $this->lines)); }

    /** @return list<OrderLine> */
    public function lines(): array       { return $this->lines; }
    public function status(): OrderStatus { return $this->status; }

    private function transition(OrderStatus $to): void
    {
        if (!$this->status->canTransitionTo($to)) {
            throw new DomainException("Переход {$this->status->value} → {$to->value} запрещён");
        }
        $this->status = $to;
    }
}

🔬 Под капотом: private-конструктор + два статических: open() и restore()

Это разделение «создать новое» и «восстановить существующее» — стандартная форма для сущностей. open() — точка входа для бизнеса (пустой заказ в статусе draft). restore() — точка входа для репозитория (сессия 3.4), который знает всё и ничего не проверяет. Оба static, потому что объекта ещё нет. Оба возвращают self, класс final.

restore() присваивает private-свойства снаружи конструктора — это разрешено, потому что код находится внутри класса: private — про класс, а не про объект. Тот же приём делает возможным equals(): $this->cents === $other->cents читает private другого объекта того же класса.

namespace App\Infrastructure\Persistence;

use App\Domain\Money;
use App\Domain\Order\{Order, OrderLine, OrderNotFound, OrderRepository, OrderStatus};

final class EloquentOrderRepository implements OrderRepository

    {
        OrderRecord::query()->updateOrCreate(['id' => $order->id], [
            'email'  => $order->email,
            'status' => $order->status()->value,
            'lines'  => array_map(
                fn (OrderLine $l) => ['name' => $l->name, 'unit_cents' => $l->unitPrice->cents, 'qty' => $l->qty],

<?php
// app/Http/Controllers/OrderController.php

namespace App\Http\Controllers;

use App\Domain\Menu\BeverageBuilder;
use App\Domain\Order\{Order, OrderLine, OrderRepository};
use Illuminate\Http\{JsonResponse, Request};
use Illuminate\Support\Str;

final class OrderController extends Controller
{
    public function __construct(
        private readonly OrderRepository $orders,      // интерфейс: контроллер не знает про Eloquent
        private readonly BeverageBuilder $builder,
    ) {}

    public function store(Request $request): JsonResponse
    {
        $data = $request->validate([
            'email'          => ['nullable', 'email'],
            'items'          => ['required', 'array', 'min:1'],
            'items.*.drink'  => ['required', 'string'],
            'items.*.size'   => ['required', 'string'],
            'items.*.extras' => ['array'],
            'items.*.qty'    => ['integer'],
        ]);

        $order = Order::open((string) Str::ulid(), $data['email'] ?? null);
        foreach ($data['items'] as $item) {
            $order->add($this->builder->build($item['drink'], $item['size'], $item['extras'] ?? []), $item['qty'] ?? 1);
        }
        $this->orders->save($order);

        return response()->json($this->present($order), 201);
    }

    public function show(string $id): JsonResponse
    {
        return response()->json($this->present($this->orders->get($id)));
    }

    private function present(Order $order): array
    {
        return [
            'id'       => $order->id,
            'status'   => $order->status()->value,
            'lines'    => array_map(fn (OrderLine $l) => ['name' => $l->name, 'qty' => $l->qty, 'total' => $l->total()->format()], $order->lines()),
            'subtotal' => $order->subtotal()->format(),
        ];
    }
}

Шаг 4.1DiscountPolicy: пять стратегий + Clock как интерфейс#

final class BulkDiscount implements DiscountPolicy
{
    public function __construct(private readonly int $minItems, private readonly DiscountPolicy $inner) {}
    public function discountFor(Order $order): Money
    {
        return $order->itemCount() >= $this->minItems ? $this->inner->discountFor($order) : Money::zero();
    }
}

// app/Domain/Pricing/HappyHourDiscount.php — композиция + зависимость от Clock
final class HappyHourDiscount implements DiscountPolicy
{
    public function __construct(
        private readonly Clock $clock,
        private readonly int $fromHour,
        private readonly int $toHour,
        private readonly DiscountPolicy $inner,
    ) {}

    public function discountFor(Order $order): Money
    {
        $hour = (int) $this->clock->now()->format('G');
        return ($hour >= $this->fromHour && $hour < $this->toHour) ? $this->inner->discountFor($order) : Money::zero();
    }
}

// app/Domain/Pricing/BestOf.php — из нескольких акций клиенту достаётся лучшая
final class BestOf implements DiscountPolicy
{
    /** @param list<DiscountPolicy> $policies */
    public function __construct(private readonly array $policies) {}

    public function discountFor(Order $order): Money
    {
        $best = Money::zero();
        foreach ($this->policies as $policy) {
            $d = $policy->discountFor($order);
            if ($d->isGreaterThan($best)) { $best = $d; }
        }
        return $best;
    }
}

🔬 Под капотом: bind vs singleton, и contextual binding как второй способ назначить стратегию

bind создаёт объект при каждом резолве, singleton — один на процесс. Для DiscountPolicy мы взяли bind, чтобы в тестах (сессия 5) config(['cafe.discount' => ...]) действовал на следующий запрос. У стратегий без состояния разницы в поведении нет — только в количестве объектов.

Contextual binding назначает реализацию не глобально, а «для этого класса»:

$this->app->when(PaymentController::class)->needs(DiscountPolicy::class)->give(fn () => new PercentDiscount(10));
$this->app->when(SomeReportService::class)->needs(DiscountPolicy::class)->give(NoDiscount::class);

Так один интерфейс получает разные реализации в разных местах, а сами классы об этом не знают. Плюс: вся сборка в провайдере. Минус: читая PaymentController, вы не видите, какая скидка применяется, — надо идти в провайдер. Для десятка классов удобнее биндинг по конфигу; для сотни — contextual.

    {
        $message = new AMQPMessage(json_encode($payload, JSON_THROW_ON_ERROR | JSON_UNESCAPED_UNICODE), [

            $this->channel    = $this->connection->channel();
        }
        return $this->channel;
    }

    {
        $this->channel?->close();
        $this->connection?->close();
    }

Шаг 5.2AbstractAmqpWorker, worker:barista, worker:notify, Notifier (Log / Mail / Null)#

Базовый воркер — упрощённый AbstractAmqpWorker: полную версию, с идемпотентностью и retry, вы напишете позже в RabbitMQ Lab, а здесь — минимум для одного happy path. Новое здесь одно: зависимости воркера приходят в конструктор, потому что handle() у родителя final.

<?php
// app/Console/Commands/Workers/AbstractAmqpWorker.php
declare(strict_types=1);

namespace App\Console\Commands\Workers;

use App\Infrastructure\Amqp\AmqpConnectionFactory;
use Illuminate\Console\Command;
use PhpAmqpLib\Exception\AMQPTimeoutException;
use PhpAmqpLib\Message\AMQPMessage;

abstract class AbstractAmqpWorker extends Command
{
    private bool $stopping = false;

    abstract protected function queue(): string;
    abstract protected function consumerName(): string;
    /** Бизнес-логика. Исключение → nack без requeue. */
    abstract protected function process(array $payload): void;

    final public function handle(AmqpConnectionFactory $factory): int
    {
        pcntl_async_signals(true);
        pcntl_signal(SIGTERM, fn () => $this->stopping = true);
        pcntl_signal(SIGINT,  fn () => $this->stopping = true);

        $conn = $factory->connect();
        $ch   = $conn->channel();
        $ch->basic_qos(0, 1, false);
        $ch->basic_consume(
            queue: $this->queue(), consumer_tag: $this->consumerName() . '-' . getmypid(), no_ack: false,
            callback: fn (AMQPMessage $m) => $this->handleMessage($m),
        );
        $this->info("[{$this->consumerName()}] listening {$this->queue()}");

        while ($ch->is_consuming() && !$this->stopping) {
            try { $ch->wait(timeout: 1); } catch (AMQPTimeoutException) {}
        }
        $ch->close(); $conn->close();
        return self::SUCCESS;
    }

    private function handleMessage(AMQPMessage $msg): void
    {
        $this->line("← {$msg->get('message_id')}" . ($msg->get('redelivered') ? ' (REDELIVERED)' : ''));
        try {
            $this->process(json_decode($msg->getBody(), true, flags: JSON_THROW_ON_ERROR));
        } catch (\Throwable $e) {
            $this->error("   ✖ {$e->getMessage()} → nack(requeue=false)");
            $msg->nack(requeue: false);
            return;
        }
        $msg->ack();
        $this->info('   ✔ ack');
    }
}

$this->app->instance(X::class, $obj) — «на этот интерфейс всегда отдавай вот этот объект»; перекрывает биндинг из провайдера на время теста. Именно поэтому тест держит ссылку на $this->events — это тот же объект, который получит контроллер.

Это тонкое расхождение семантик двух реализаций одного интерфейса: интерфейс гарантирует наличие метода, но не одинаковость всех побочных эффектов. Хотите строже — клонируйте при save() и get().

11. Глоссарий #

Класс — описание типа объектов: какие свойства и методы. Создаётся один раз в коде.
Объект (экземпляр) — конкретная вещь, созданная по классу через new; со своим состоянием и идентичностью.
Свойство — переменная внутри объекта — его состояние.
Метод — функция внутри объекта — его поведение; имеет доступ к $this.
Конструктор — метод __construct, вызываемый при new; приводит объект в корректное начальное состояние. Место для проверок, которые нельзя обойти.
Promotion — объявление свойства прямо в параметре конструктора: __construct(private readonly Size $size).
Видимость — public — всем; protected — классу и наследникам; private — только классу (не объекту: два объекта одного класса видят private друг друга).
Инкапсуляция — данные + код, который их меняет, в одном месте; снаружи — только безопасный API; цель — защита инвариантов.
Инвариант — условие, всегда истинное для корректного объекта: «сумма ≥ 0», «оплаченный заказ не меняется».
Абстракция — контракт без реализации: абстрактный класс или интерфейс. Клиентский код пишется в её терминах.
Абстрактный класс — класс с реализацией и «дырками»; не инстанцируется; один родитель у потомка.
Интерфейс — только сигнатуры; много интерфейсов у класса; реализации не делят код.
Трейт — вклеиваемый кусок кода; не контракт, не заменяем через DI.
Enum — тип с фиксированным набором значений и методами; замена «магическим строкам».
Наследование — отношение «является»: потомок получает члены родителя. Для общего неизменного скелета.
Композиция — отношение «содержит / использует»: объект держит другой и делегирует. Для всего, что меняется и комбинируется.
Полиморфизм — один вызов — разное поведение по реальному типу объекта, без if у вызывающего.
Template Method — родитель фиксирует скелет (final), дети реализуют шаги (abstract) или переопределяют хуки.
Хук — необязательный метод с дефолтным телом, который потомок может переопределить.
Strategy — заменяемое поведение как объект с интерфейсом, передаваемый снаружи.
Decorator — обёртка того же интерфейса, добавляющая поведение до/после делегирования; вкладывается в цепочку.
Factory — единственное место, где из «сырых» данных (строка) создаётся объект нужного класса.
Value Object — неизменяемое значение без идентичности; равенство по содержимому.
Entity — объект с идентичностью и жизненным циклом; меняет состояние только через методы с бизнес-именами.
Repository — интерфейс «сохранить / найти», скрывающий хранилище от домена.
Null Object — реализация интерфейса, которая ничего не делает; заменяет null.
Dependency Injection — объект получает зависимости снаружи (конструктор), а не создаёт их.
Service Container — механизм Laravel, создающий объекты по типам конструктора; биндинг связывает интерфейс с реализацией.
Contextual binding — «когда создаёшь X и ему нужен Y — дай Z»: разные реализации одного интерфейса для разных классов.
Dependency Inversion — зависеть от абстракций; стрелка зависимости от инфраструктуры к домену, не наоборот.
Liskov Substitution — реализацию можно подставить вместо абстракции без изменения поведения клиента — включая неписаные ожидания.
Тестовый двойник — реализация интерфейса для теста: stub (возвращает заготовленное), spy (запоминает вызовы), fake (упрощённая рабочая версия — InMemory).
readonly — свойство записывается один раз; защищает ссылку, не содержимое объекта по ней.
final — запрет наследования/переопределения: «расширяй композицией».
self / static — self — класс, где написан код; static — класс, у которого реально вызвали (late static binding).
First-class callable — $obj->method(...) — метод как замыкание (PHP 8.1).
